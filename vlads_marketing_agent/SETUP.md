# SETUP.md — Інструкція з налаштування агента Vlad's Marketing

Ця інструкція розрахована на людину **без досвіду програмування**. Виконуйте
кроки по порядку, нічого не пропускаючи. На все піде приблизно 30-40 хвилин.

> Агент шукає малий та середній бізнес (кав'ярні, меблеві магазини,
> e-commerce тощо), аналізує їхню онлайн-присутність через Claude API і
> готує персоналізовані листи-чернетки в Gmail. **Жоден лист ніколи не
> надсилається автоматично** — ви завжди самі натискаєте "Надіслати" в Gmail.

## 1. Створення проєкту в Google Cloud Console

1. Відкрийте у браузері: https://console.cloud.google.com/
2. Увійдіть під тим Google-акаунтом (Gmail), з якого агент буде надсилати
   листи (наприклад, робоча пошта Vlad's Marketing).
3. Угорі, поряд з логотипом Google Cloud, натисніть на випадаючий список
   проєктів → **"New Project" ("Новий проєкт")**.
4. Введіть назву, наприклад `vlads-marketing-agent`, і натисніть
   **"Create" ("Створити")**.
5. Зачекайте 10-20 секунд, поки проєкт створиться, і переконайтеся, що він
   вибраний угорі (назва проєкту видно біля логотипу).

## 2. Увімкнення Gmail API та Places API

1. У лівому меню (значок ☰) відкрийте **"APIs & Services" → "Library"**
   ("API та сервіси" → "Бібліотека").
2. У пошуку введіть `Gmail API`, відкрийте картку **Gmail API** і натисніть
   синю кнопку **"Enable" ("Увімкнути")**.
3. Поверніться до бібліотеки (кнопка "назад" або знову "Library"), у пошуку
   введіть `Places API` (саме "Places API", **не** "Places API (New)" —
   агент використовує класичний Text Search/Details).
4. Відкрийте картку **Places API** і натисніть **"Enable"**.

Якщо Google запропонує увімкнути білінг (Billing) для проєкту — це
нормально, Google Places API вимагає прив'язану картку навіть для
безкоштовного ліміту запитів на місяць. Anthropic API оплачується окремо,
через console.anthropic.com (див. крок 5).

## 3. Отримання OAuth credentials.json для Gmail

1. У лівому меню відкрийте **"APIs & Services" → "OAuth consent screen"**
   ("Екран згоди OAuth").
2. Оберіть тип **"External" ("Зовнішній")** (якщо у вас немає Google
   Workspace-організації) → **"Create"**.
3. Заповніть обов'язкові поля: назва застосунку (наприклад
   `Vlad's Marketing Agent`), ваш email як контактний email розробника.
   Решту полів можна залишити порожніми. Натисніть **"Save and Continue"**
   кілька разів, поки не дійдете до кінця майстра.
4. На кроці **"Test users" ("Тестові користувачі")** додайте ваш власний
   Gmail-акаунт (той, з якого будуть надсилатись листи) — це важливо, інакше
   Google не дозволить авторизуватись.
5. Тепер перейдіть у **"APIs & Services" → "Credentials"** ("Облікові дані").
6. Натисніть **"Create Credentials" → "OAuth client ID"**.
7. У полі **"Application type"** оберіть **"Desktop app"** ("Настільний
   застосунок"). Дайте йому назву, наприклад `Vlad's Marketing CLI`.
8. Натисніть **"Create"**. З'явиться вікно з ID клієнта — натисніть
   **"Download JSON"**.
9. Перейменуйте завантажений файл на `credentials.json` і покладіть його в
   корінь папки проєкту (туди ж, де лежить файл `main.py`).

> ⚠️ Файл `credentials.json` — це облікові дані, а не пароль напряму, але
> все одно тримайте його приватним і не публікуйте в інтернеті/репозиторії.
> Файл вже додано в `.gitignore`, тому Git не закомітить його випадково.

## 4. Отримання API-ключа для Places API

1. У тому ж розділі **"APIs & Services" → "Credentials"** натисніть
   **"Create Credentials" → "API key"**.
2. Google згенерує ключ виду `AIzaSy...` — скопіюйте його.
3. (Рекомендовано) Натисніть на щойно створений ключ → у розділі
   **"API restrictions"** оберіть **"Restrict key"** і залиште позначеним
   лише **"Places API"** — це захистить ключ від використання деінде, якщо
   він випадково витече.
4. Цей ключ ви вставите у файл `.env` як значення `GOOGLE_PLACES_API_KEY`
   (див. крок 6).

## 5. Отримання Anthropic API-ключа

1. Відкрийте https://console.anthropic.com/settings/keys
2. Увійдіть або зареєструйтесь.
3. Натисніть **"Create Key"**, дайте ключу назву (наприклад
   `vlads-marketing-agent`) і скопіюйте його. Ключ завжди починається з
   `sk-ant-`.
4. Поповніть баланс на цьому ж акаунті (розділ **"Billing"**), якщо ще не
   робили цього раніше — без балансу виклики API повертатимуть помилку.
5. Цей ключ ви вставите у файл `.env` як значення `ANTHROPIC_API_KEY`.

## 6. Встановлення Python-залежностей

Потрібен встановлений Python 3.11 або новіший
(https://www.python.org/downloads/).

1. Відкрийте термінал (Термінал на macOS/Linux, PowerShell/CMD на Windows)
   і перейдіть у папку проєкту:

   ```bash
   cd шлях/до/vlads_marketing_agent
   ```

2. (Рекомендовано) Створіть ізольоване віртуальне середовище:

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate        # macOS/Linux
   .venv\Scripts\activate           # Windows (PowerShell/CMD)
   ```

3. Встановіть залежності:

   ```bash
   pip install -r requirements.txt
   ```

   (Для розробки/тестів додатково: `pip install -r requirements-dev.txt`)

4. Скопіюйте приклад файлу середовища та відкрийте його в будь-якому
   текстовому редакторі (Notepad, TextEdit, VS Code):

   ```bash
   cp .env.example .env
   ```

5. Заповніть у `.env` значення:
   - `GOOGLE_PLACES_API_KEY` — ключ з кроку 4.
   - `ANTHROPIC_API_KEY` — ключ з кроку 5.
   - `GMAIL_SENDER_EMAIL` — ваша Gmail-адреса Vlad's Marketing.
   - Решту полів можна залишити типовими значеннями.

6. Перевірте (і за потреби відредагуйте) файл `leads_config.yaml` — там
   вказано, які категорії бізнесу та локації шукати, і скільки максимум
   нових лідів створювати за один запуск.

## 7. Перша авторизація Gmail (один раз)

Ця дія відкриє браузер і попросить вас увійти в Gmail-акаунт та дати
агенту дозвіл створювати чернетки й читати листи (без права відправки).

1. Переконайтеся, що файл `credentials.json` лежить у корені проєкту
   (крок 3) і що `.env` заповнений (крок 6).
2. Запустіть будь-яку команду, що використовує Gmail, наприклад:

   ```bash
   python main.py draft --dry-run
   ```

   Якщо лідів ще немає — це нормально, головне, що на цьому кроці
   перевіряється сама авторизація за потреби. Щоб гарантовано побачити
   вікно браузера прямо зараз, найпростіше один раз запустити реальний
   (не dry-run) запуск `check-replies` після появи хоча б однієї надісланої
   чернетки, АБО скористатись `python main.py draft` після того, як у базі
   з'явиться проаналізований лід.
3. У браузері, що відкриється: увійдіть під Gmail-акаунтом Vlad's
   Marketing → погодьтесь на запитані дозволи ("Compose email drafts",
   "View your email messages"). Google може показати попередження
   "Google hasn't verified this app" — це очікувано для власного
   тестового застосунку; натисніть **"Advanced" → "Go to ... (unsafe)"**,
   бо це саме ваш застосунок.
4. Після підтвердження браузер покаже "You may close this window" —
   можна закрити вкладку. У корені проєкту з'явиться файл `token.json` —
   він зберігає токен доступу, щоб не проходити авторизацію щоразу.

Якщо колись побачите помилку про протермінований/відкликаний токен —
просто видаліть `token.json` і повторіть цей крок.

## 8. Перевірка перед запуском

**Перш ніж вставляти реальні ключі й запускати щось насправді, перевірте
поведінку агента безпечно:**

1. Спробуйте кожну команду з прапорцем `--dry-run` — вона виконає всю
   логіку, але замість реальних викликів API лише покаже в консолі, що
   було б зроблено:

   ```bash
   python main.py discover --dry-run
   python main.py enrich --dry-run
   python main.py analyze --dry-run
   python main.py draft --dry-run
   python main.py check-replies --dry-run
   python main.py pipeline --dry-run
   ```

2. Коли `.env`, `credentials.json` та `leads_config.yaml` готові, запустіть
   фінальну перевірку:

   ```bash
   python validate_setup.py
   ```

   Скрипт виведе чіткий чек-лист ✅/❌ по кожному пункту (змінні
   середовища, формат ключа Anthropic, структура `credentials.json`,
   доступність усіх Python-залежностей, валідність `leads_config.yaml`).
   Виправте все, що позначено ❌, і запустіть скрипт ще раз.

3. Лише після того, як `validate_setup.py` показує все зеленим, запускайте
   реальний пайплайн (без `--dry-run`):

   ```bash
   python main.py pipeline
   ```

## 9. Приклади команд для щоденного використання

```bash
# Знайти нових потенційних клієнтів (Модуль 1)
python main.py discover

# Зібрати дані про сайти нових лідів (Модуль 2)
python main.py enrich

# Проаналізувати слабкі місця через Claude (Модуль 3)
python main.py analyze

# Створити персоналізовані чернетки листів у Gmail (Модуль 4)
python main.py draft

# Перевірити, чи хтось відповів, і підготувати презентацію (Модуль 5)
python main.py check-replies

# Те саме, але періодично (раз на CHECK_REPLIES_INTERVAL_MINUTES хвилин)
python main.py check-replies --watch

# Запустити пошук + збагачення + аналіз + чернетки одним викликом
python main.py pipeline

# Подивитись, скільки лідів на якому етапі
python main.py status
```

**Типовий робочий день:**

1. Вранці: `python main.py pipeline` — знайде нових лідів і підготує
   чернетки листів.
2. Відкрийте Gmail → папка "Чернетки" → перегляньте та за бажанням
   відредагуйте кожен лист → натисніть **"Надіслати"** вручну для тих, що
   схвалюєте.
3. Протягом дня: `python main.py check-replies` (або залиште працювати у
   фоні з `--watch`) — коли клієнт відповість, агент підготує презентацію
   та чернетку відповіді з вкладенням.
4. Раз на день: `python main.py status` — швидкий погляд на воронку.

### Ручне збагачення лідів без сайту

Якщо в бізнесу немає сайту, лише Instagram/Facebook, агент **не** заходить
туди сам (це порушувало б умови використання цих сервісів). Замість цього
такий лід отримує статус `needs_manual_screenshot`. Щоб додати дані
вручну: відкрийте профіль у соцмережі, скопіюйте текст опису/останніх
постів і в Python-консолі (або невеликому скрипті) викличте:

```python
from src.config import load_settings
from enrichment import add_manual_data

settings = load_settings()
add_manual_data(settings, lead_id=42, screenshot_text="Текст з Instagram-профілю...")
```

Після цього лід автоматично потрапить у наступний запуск `analyze`.

## 10. Що робити, якщо щось пішло не так

- **"Відсутні обов'язкові змінні середовища"** — перевірте `.env`,
  переконайтесь, що скопіювали `.env.example → .env` і заповнили ключі.
- **"credentials.json не знайдено"** — переконайтесь, що файл лежить саме
  в корені проєкту (поряд з `main.py`), а не в підпапці "Downloads".
- **"Токен протермінований / потрібна повторна авторизація"** — видаліть
  файл `token.json` і запустіть команду ще раз, щоб пройти авторизацію в
  браузері заново (крок 7).
- **"Немає лідів у статусі ... для ..."** — це нормальне попередження, а
  не помилка: спочатку виконайте попередній етап пайплайну (наприклад,
  перед `analyze` має відпрацювати `enrich`).
- **Помилки Google Places / Anthropic про перевищення ліміту (rate
  limit)** — агент автоматично повторює запит до 3 разів із зростаючою
  паузою; якщо помилка залишається — зачекайте кілька хвилин і спробуйте
  знову, або перевірте баланс/квоти у відповідній консолі.
- Усі детальні логи зберігаються у файлі `logs/agent.log` (з ротацією) —
  перший крок діагностики будь-якої проблеми.
